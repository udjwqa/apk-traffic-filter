# Panel - Приватная админ-панель для управления APK-трафиком

Закрытая панель управления для мониторинга, фильтрации и маршрутизации трафика Android-приложений. Разделяет поток на "серый" (реальные юзеры) и "белый" (боты, модераторы, подозрительный трафик) на основе скоринговой системы.

Весь фронт сделан и готов к работе. Бэкенд пока на моках — в коде везде стоят `TODO(backend)` маркеры, по ним легко найти точки подключения реального API.

---

## Стек

- **Next.js 16** (App Router) + **React 19** + **TypeScript**
- **Tailwind CSS v4** + **shadcn/ui** (base-ui компоненты)
- **Prisma** + **SQLite** (для авторизации, легко мигрировать на Postgres)
- **NextAuth v5** (credentials provider, bcrypt)
- **Recharts** (графики)
- **Lucide React** (иконки)

## Что внутри — 6 вкладок

### 1. Дашборд (`/dashboard`)
Главный экран с real-time мониторингом. Тут видно что происходит прямо сейчас:

- **5 карточек метрик** — запросы за 24ч, серый/белый поток с процентами, активные баны, текущий RPS (с пульсирующим индикатором)
- **Линейный график** — распределение серого vs белого трафика по часам за сутки
- **Круговая диаграмма** — топ причин отказа (google_asn, device_blocked, vpn_detected и тд)
- **Real-time лента запросов** — таблица куда в реальном времени падают логи. Есть пауза, очистка, счетчик. Клик по строке открывает модалку с полным JSON-дампом (заголовки, JS-метрики, ответ Play Integrity)

Лента сейчас работает через setInterval (имитация WebSocket). В коде отмечено `TODO(websocket)` — когда будет реальный бэк, просто подключаешь WS и все.

### 2. Журнал аудита (`/dashboard/activity`)
Архив всех запросов с мощной фильтрацией:

- **Поиск** по IP, User-Agent, Device ID
- **Фильтры** — вердикт (серый/белый), код отказа, страна, диапазон дат
- **Пагинация** — 25 записей на страницу
- **Быстрые действия** — кнопка "Забанить IP" и "В белый список" прямо в строке таблицы, с подтверждением
- **Экспорт в CSV** — выгружает отфильтрованные логи для аналитиков

### 3. Конфигурация движка (`/dashboard/settings`)
Настройка порогов скоринга без правки кода:

- **Системные пороги** — слайдер проходного балла (0-100), переключатель IPQS_FAIL_OPEN, выбор минимального вердикта Play Integrity
- **Поведенческие триггеры** — пороги для JS-анализа: время зарядки батареи, неподвижность акселерометра, скорость кликов, расхождение таймзон
- **Веса скоринга** — баллы за каждый тип подозрительной активности (VPN/Proxy, подозрительный город, английский WebView, хостинг-краулер, клики без тача, несовпадение таймзоны)
- Кнопка "Сохранить конфиг" + "Сбросить к дефолту", индикатор несохраненных изменений

### 4. Управление списками (`/dashboard/security`)
Визуальный редактор стоп-листов (файлы `server/lists/*.txt`):

- **7 блоков** с тег-инпутами (красивые чипсы с крестиками):
  - `countries_block.txt` — страны для блокировки
  - `cities_block.txt` — города модерации (Mountain View, Dublin и тп)
  - `user_agents_block.txt` — стоп-лист ботов (Googlebot, GPTBot и тд)
  - `device_models_block.txt` — модели Pixel/Google
  - `codenames_block.txt` — кодовые имена эмуляторов
  - `isp_block.txt` — провайдеры (Google LLC, Amazon, DigitalOcean)
  - `gpu_block.txt` — GPU-драйверы эмуляторов (SwiftShader, VirtualBox)
- Добавление через Enter, запятую или paste. Сохранение поблочно или "Сохранить все"

### 5. Репозиторий банов (`/dashboard/users`)
Управление черным и белым списками:

- **Черный список IP** — все забаненные адреса с указанием источника (ручной, honeypot, автоматический, cloudflare). Кнопка "Разбанить" + "Добавить бан"
- **Белый список** — IP/Device ID разработчиков и тестеров, которые всегда проходят на серую ссылку. Кнопка "Добавить исключение" + "Удалить"
- Поиск в обеих таблицах

### 6. Управление офферами (`/dashboard/apps`)
Менеджмент целевых URL:

- **Белая ссылка (Safe URL)** — куда шлем ботов/модераторов (заглушка, фейк)
- **Серая ссылка (Target URL)** — реальный продукт для живых юзеров
- **Тип белого потока** — что именно показывать белому трафику: 403, 404, редирект на Safe URL, или фейковый HTML

## UX-фичи

- **Кнопка "Паника"** — красная кнопка в шапке, доступна со всех вкладок. Включает режим 100% белого потока (все запросы на заглушку). Юзай если Google внезапно начал штормить модерацию
- **Индикаторы статуса** — в шапке видно состояние CF Worker и FastAPI Backend (зеленые точки = ок)
- **Mock-данные toggle** — переключатель в sidebar внизу. Включает/выключает моковые данные на всех вкладках разом. Когда подключишь реальный бэк — просто выключи мок

## Быстрый старт (разработка)

```bash
# 1. Клонируй репу
git clone <repo-url> panel
cd panel

# 2. Установи зависимости
npm install

# 3. Создай .env из шаблона
cp .env.example .env
# Сгенерируй секрет:
# openssl rand -hex 32
# Вставь его в AUTH_SECRET в .env

# 4. Подготовь базу
npx prisma generate
npx prisma db push
npx tsx prisma/seed.ts

# 5. Запускай
npm run dev
```

Откроется на `http://localhost:3000`

## Деплой на Ubuntu 24.04

### Подготовка сервера

```bash
# Обнови систему
sudo apt update && sudo apt upgrade -y

# Установи Node.js 20+ (через NodeSource)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# Проверь версию
node -v  # должно быть v20+
npm -v

# Установи PM2 для управления процессом
sudo npm install -g pm2
```

### Деплой панели

```bash
# 1. Закинь файлы на сервер (scp, git clone, что угодно)
cd /opt
git clone <repo-url> panel
cd panel

# 2. Создай .env
cp .env.example .env
nano .env
# DATABASE_URL="file:./dev.db"
# AUTH_SECRET="сгенерируй-openssl-rand-hex-32"

# 3. Установи зависимости и собери
npm install
npx prisma generate
npx prisma db push
npx tsx prisma/seed.ts
npm run build

# 4. Запусти через PM2
pm2 start npm --name "panel" -- start
pm2 save
pm2 startup  # чтобы автозапуск после ребута

# 5. Проверь
curl http://localhost:3000
```

### Nginx (опционально, если нужен домен/SSL)

```nginx
server {
    listen 80;
    server_name panel.example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_cache_bypass $http_upgrade;
    }
}
```

Потом `sudo certbot --nginx -d panel.example.com` для SSL.

## Подключение реального бэкенда

Все точки интеграции помечены в коде. Найти их:

```bash
grep -rn "TODO(backend)" src/
grep -rn "TODO(websocket)" src/
```

Основные шаги:
1. **REST API** — замени вызовы mock-функций на `fetch()` к своему бэкенду в файлах `src/hooks/` и `src/lib/services/`
2. **WebSocket** — подключи реальный WS в `src/hooks/use-request-feed.ts` (там есть закомментированный пример)
3. **Авторизация** — если нужна другая схема, правь `src/lib/auth.ts`
4. **БД** — для продакшна замени SQLite на Postgres в `prisma/schema.prisma`
5. Выключи мок-данные через toggle в sidebar — и панель готова к реальным данным
